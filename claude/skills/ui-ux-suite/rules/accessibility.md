# Accessibility Rules

## Keyboard

All core functionality must be usable without a mouse.

## Focus

Focus must be visible.

Hover, focus, pressed, selected, and disabled are distinct states.

Never remove focus outline without an accessible replacement.

## Semantics

Use controls according to their meaning.

Navigation:
link

Action:
button

Multi-select:
checkbox

One-of-many:
radio

Immediate binary setting:
switch

## Labels

Inputs require persistent labels or equivalent accessible names.

## Error

Error must:
- identify the affected field/context
- explain the problem
- provide recovery guidance where possible

## Color

Never rely only on color for:
- error
- success
- selected
- status
- required
- chart distinction

## Motion

Support reduced motion.

## Touch

Avoid tiny or crowded targets.

## Content

Use plain language for:
- destructive consequences
- error messages
- permissions
- irreversible operations

## Dynamic Feedback

Loading, success, and error changes should be perceivable and not silently alter context.
