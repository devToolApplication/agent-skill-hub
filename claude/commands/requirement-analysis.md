# Requirement Analysis

Làm rõ yêu cầu, scope, assumptions, constraints trước khi chuyển Dev/Architect.

## Khi nào dùng
- User yêu cầu mơ hồ
- Feature mới chưa có spec
- Cần phân tích nghiệp vụ
- Trước khi viết user story/AC

## Workflow
1. Restate requirement bằng ngôn ngữ rõ ràng.
2. Xác định actor, goal, trigger.
3. Define in-scope/out-of-scope.
4. Extract business rules.
5. Identify assumptions and constraints.
6. List open questions.
7. Propose next role/action.

## Output
- Problem statement
- Actors
- Goals
- Scope
- Business rules
- Assumptions
- Constraints
- Open questions

## Checklist
- [ ] Không còn thuật ngữ mơ hồ
- [ ] Scope có boundary rõ
- [ ] Business rules tách khỏi UI details
- [ ] Open questions được gom lại
