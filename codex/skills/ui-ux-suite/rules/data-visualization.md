# Data Visualization Rules

## Start With the Question

Choose a chart based on what the user must understand.

Comparison:
bar chart

Trend over time:
line chart

Part-to-whole:
stacked bar, 100% stacked bar, or limited pie/donut when categories are few

Distribution:
histogram / box plot

Relationship:
scatter plot

Exact lookup:
table

## Avoid Decorative Charts

Do not add a chart simply to fill dashboard space.

Every chart should answer a question.

## Color

Use restrained palettes.

Do not create 12 unrelated saturated series colors if grouping, labels, or interaction can reduce complexity.

Do not rely only on color to distinguish series.

## Labels

Prefer direct labeling when it reduces legend lookup.

## Axes

Do not distort scale to exaggerate differences.

Bar charts generally should use a meaningful zero baseline.

## Dashboard Hierarchy

Order:

1. critical KPIs
2. trends
3. exceptions / alerts
4. actionable detail

A dashboard should answer:
- What is happening?
- What changed?
- What needs attention?
- What can I do?

## Empty / Loading / Error

Charts require the same state design as other components.
